# Contributing

Keep each skill focused on one step. Add lessons supported by real decisions; avoid project-specific presets or universal rules from one review.

1. Describe the failure/outcome with fictional people and generic paths.
2. Edit the smallest relevant skill/template. Essential safeguards belong in each skill; shared docs are supplemental.
3. Run python3 scripts/validate.py and try realistic scenarios with an independent agent. Record decisions and limits in [validation](docs/validation.md).
4. Bump changed skill versions and all release manifests, update the changelog and tag after checks pass.

Publish instructions and synthetic examples only. Exclude media, project exports, licensed LUTs/fonts, private links, client paths, credentials and real subjects' identities. Do not claim a new Resolve version or assistant runtime is tested until exercised.
